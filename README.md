# Chess Piece Detection Pipeline

Детекция и распознавание позиции на шахматной доске по фото/видео: bbox фигур →
тип+цвет → клетка на доске → нотация хода → валидация → 2D-отрисовка позиции.
Финальная цель — интеграция с роборукой: камера смотрит на доску, пайплайн
определяет позицию и говорит роботу, как играть, либо сигнализирует, что
сделанный человеком ход невалиден и фигуру нужно вернуть на место.

## Архитектура

Detect + classify — два отдельных этапа, а не единый многоклассовый детектор:

1. **Детектор** (1 класс `piece`) — только находит bbox фигур.
2. **Классификатор** (12 классов: тип+цвет) — определяет, что за фигура, по
   вырезанному кропу.

Разделение принято осознанно: единый 12-классовый детектор путал **цвет**
фигур на реальном видео (domain gap по освещению/тону дерева), хотя тип
определял верно. Архитектура detect+classify позволяет унести проблему цвета
в отдельный, более узкий классификатор.

### Модули

| Файл | Роль |
|---|---|
| `pipeline_predict.py` | Простой инференс на видео: детект → классификация → отрисовка bbox+лейбл на кадре |
| `homography_test.py` | Перевод bbox → клетка доски (a1-h8) через `cv2.getPerspectiveTransform`; тест точности на разметке ChessReD |
| `board_state.py` | `board_to_state()` (chess.Board → словарь клетка:фигура), `infer_move()` (определяет и валидирует ход через python-chess: `no_change`/`valid`/`invalid`) |
| `board_corners.py` | Определение углов доски для гомографии: автодетект по внешнему контуру + ручная калибровка кликом + сохранение калибровки на сессию |
| `stable_detector.py` | `StableBoardDetector` — сглаживание дёрганья/ложных срабатываний голосованием по последним N кадрам; `sanity_check()` — проверка физической валидности состояния доски (не больше 32 фигур, ровно 1 король на цвет) |
| `full_pipeline.py` | Собирает всё вместе: `process_turn()` (один кадр → ход), `run_sequence()` (серия кадров датасета), `process_video_stream()` (реальное видео целиком, с антидёрганьем), `render_board_2d()` (SVG-рендер текущей позиции) |

## Датасет

Используется подвыборка **ChessReD2K** из [ChessReD](https://github.com/tmasouris/end-to-end-chess-recognition) (1442 train / 330 val / 306 test реальных фото со смартфонов, bbox фигур + углы доски).

### Скачать датасет

```bash
git clone https://github.com/tmasouris/end-to-end-chess-recognition.git
cd end-to-end-chess-recognition
sudo apt install python3-tk
pip install pandas ttkthemes
python3 chessred.py --dataroot ../chessred_data --download
```

### Подготовить данные для детектора (1 класс "piece")

```bash
python3 convert_to_yolo_single_class.py
```
Результат: `chessred2k_yolo_singleclass/` (train/val/test в YOLO-формате, все фигуры — класс 0).

### Подготовить данные для классификатора (12 классов: тип + цвет)

```bash
python3 make_classifier_dataset.py
```
Результат: `chessred2k_classifier/` (train/val/test, картинки по папкам-классам).

Оба датасета не хранятся в git и пересоздаются этими скриптами по требованию.

## Обучение

### Детектор

```bash
yolo detect train \
    data=chessred2k_yolo_singleclass/data.yaml \
    model=yolo11m.pt \
    epochs=50 \
    imgsz=640 \
    batch=16 \
    device=0 \
    project=runs \
    name=detector
```

### Классификатор

```bash
yolo classify train \
    data=chessred2k_classifier \
    model=yolo11m-cls.pt \
    epochs=30 \
    imgsz=128 \
    batch=32 \
    device=0 \
    project=runs \
    name=classifier
```

После обучения скопируй лучшие веса в `models/` — их использует весь пайплайн:
```bash
mkdir -p models
cp runs/detect/detector/weights/best.pt models/detector.pt
cp runs/classify/classifier/weights/best.pt models/classifier.pt
```

Проверено на отложенном test-сплите — метрики совпадают с val, признаков утечки данных нет.

Отдельно: гомография (bbox → клетка a1-h8) — 99.1% точность на реальных данных
(`homography_test.py`); перевод в нотацию + валидация хода — подтверждено на
реальной последовательности из 7 ходов подряд, включая через полную цепочку
антидёрганья.

## Известные ограничения

- **Путаница цвета на реальном видео.** На видео со смартфона (не из
  датасета) классификатор иногда путает цвет тёмных деревянных фигур со
  светлым — вероятно, domain gap по тону дерева/освещению, которого нет в
  ChessReD в достаточном объёме. Усиленная HSV-аугментация при обучении
  (варьирование hue/saturation/value) была опробована и **не решила**
  проблему — визуально идентичные ошибки до и после, плюс появились
  побочные регрессии (просадка recall детектора на сценах с перекрытием,
  ложные срабатывания). Более перспективные пути: (а) реальные фото
  проблемного домена в трейне вместо синтетической аугментации, (б)
  калибровка по контексту доски (известная гомография даёт яркость
  клеток как референс), (в) вырезать доску и подставлять случайный фон
  при аугментации.
- **Автодетект углов доски (`board_corners.detect_corners_auto`) ненадёжен
  на кладных сценах.** На тестовых видео с посторонними объектами в кадре
  (шахматные часы, рука, бумаги) контур/текстура/Hough-линии цепляются за
  фигуры и посторонние объекты сильнее, чем за сам (менее контрастный) край доски.
  Рабочий путь до появления отдельной обученной модели — ручная калибровка
  кликом (`board_corners.detect_corners_manual`), которая для
  физически неподвижной камеры (как у роборуки) выполняется один раз за
  сессию.

## Инференс

### Быстрый прогон на видео (без нотации/валидации хода)

```bash
python3 pipeline_predict.py <путь_к_видео> <путь_к_результату>
```
Веса ожидаются в `models/detector.pt` и `models/classifier.pt`.

### Полный пайплайн (нотация, валидация хода, антидёрганье, 2D-рендер)

```python
from full_pipeline import process_video_stream

moves, board = process_video_stream("game.mp4")  # автокалибровка углов по первому кадру
print(moves)          # список подтверждённых ходов в порядке появления
print(board.fen())    # итоговая позиция
```
